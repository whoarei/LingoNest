# GitHub 持续集成与 Android 发布

建立时间：2026-10-24 21:50:10（Asia/Shanghai）。仓库：[whoarei/LingoNest](https://github.com/whoarei/LingoNest)。

## 持续集成

[CI 工作流](../.github/workflows/ci.yml)在分支推送、Pull Request、手动运行时执行，也供发布工作流调用。Node.js 24 执行锁定安装、版本一致性、归档编号与链接检查、单元测试、类型检查、生产构建、无预装音频检查及完整 Chromium 浏览器回归。Android 使用 Java 21、SDK 36，执行原生单元测试和 Debug APK 构建。失败时保留浏览器及原生报告。

本机浏览器回归继续使用 Edge；CI 使用 Playwright 安装的 Chromium，禁止 `test.only`，不复用未知开发服务器。旧归档中的 `artifacts/` 是被 Git 忽略的本地证据，CI 通过 `--allow-missing-artifacts` 明确跳过该目录，其他本地链接和编号继续严格检查。本机 `npm run check:docs` 保持完整检查。

## 签名材料

GitHub 仓库需要四项 Actions Secrets：

| Secret | 内容 |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | 发布 keystore 的 Base64 编码 |
| `ANDROID_KEYSTORE_PASSWORD` | keystore 密码 |
| `ANDROID_KEY_ALIAS` | 发布私钥别名 |
| `ANDROID_KEY_PASSWORD` | 发布私钥密码 |

首次配置按用户要求复用 `whoarei/peerlink` 的 Android 发布证书。通过 GitHub 官方支持的 [libsodium 公钥加密格式](https://docs.github.com/en/rest/guides/encrypting-secrets-for-the-rest-api)，在源仓库工作流中将现有 Secret 加密给目标仓库，然后写入目标 Secrets。明文不进入日志、源码或传递产物。

签名只在发布构建步骤注入，临时 keystore 在步骤退出时删除；缺少任一签名环境变量或文件即拒绝 Release 构建。Pull Request 和普通 CI 不读取发布密钥。

发布证书 SHA-256 固定为 `28c461e4f2f8612f9d7717d727e772177474798fd7c48b03ca3ffbca8c81bf0a`，发布流程同时比较 APK、keystore 与该指纹，防止误换签名。

## 发布步骤

1. 同步更新 `package.json`、`package-lock.json` 的两处版本和 Android `versionName`，递增 `versionCode`。
2. 按归档规则在 `docs/` 新建唯一的 `_<版本>版本说明.md` 文档。该文档直接用作 GitHub Release 正文，请使用可在 GitHub 中访问的外部链接。
3. 执行 `npm run check:release`、`npm run check:docs`、相关测试与构建后提交。将提交推送到 GitHub。
4. 创建匹配版本的标签，例如 `git tag -a v0.1.16 -m "LingoNest 0.1.16"`，再执行 `git push origin v0.1.16`。
5. [Release 工作流](../.github/workflows/release.yml)先运行完整 CI，再构建签名 APK，核对包名、版本号、非调试状态、证书指纹、无音频／环境文件／签名库和 SHA-256。验证通过才上传 APK、证书指纹及 `SHA256SUMS.txt`。
6. 最后一个作业使用最小 `contents: write` 权限创建草稿 Release、上传并发布。失败可重跑；已公开的同版本 Release 拒绝覆盖，应修复后递增版本。

发布入口：[GitHub Actions](https://github.com/whoarei/LingoNest/actions)；下载入口：[GitHub Releases](https://github.com/whoarei/LingoNest/releases)。下载后在安装包同目录运行 `sha256sum --check SHA256SUMS.txt`，Windows 可用 `Get-FileHash` 对照校验文件。

## 安装兼容

此前本地 APK 使用 Android Debug 证书；从 `0.1.16` 开始使用 PeerLink 的发布证书。不同证书无法覆盖安装，即使包名相同、构建号更高。旧 Debug 安装需自行保留需要的内容，再卸载并安装正式签名版本；卸载会删除应用数据。后续版本持续使用同一发布证书，可按 Android 规则覆盖升级。

CI 的浏览器夹具、原生单元测试和静态 APK 检查不能代替真机麦克风、真实 AI 服务或学习效果验收。
