# 公共目录与教学数据独立存储设计

建立时间：2026-10-24 15:10:55（Asia/Shanghai）。本轮按用户明确要求，不保留旧合并快照兼容，不执行旧数据迁移。验证见[重构记录](../issues/00047_20261024151055_公共数据独立存储重构与验证.md)。本文取代[边界复审](00024_20261024122110_框架与多课程模式边界复审.md)中保留旧七步容器的阶段方案。

## 1. 数据所有权与实际存储

| 文档 key | 所有者与载荷 |
| --- | --- |
| `lingonest.catalog.v1` | 应用公共目录：孩子、当前孩子、课程教材、来源修订、归档时间、默认课程、每个孩子指定的课程 |
| `lingonest.seven-step.v1` | 七步：内容准备记录及来源快照、生成包、学习事件、恢复点、课程确认、观察时间 |
| `lingonest.passage-path.v2` | 闯关：候选、发布包及其来源快照、作答、会话与路径状态 |
| `lingonest.deletions.v2` | 应用：跨数据所有者的删除计划、完成标记和待清理资源 |
| `lingonest.mode-settings.v1` | 应用：全局学习模式选择，独立于课程与学习数据 |

浏览器以相同 key 保存独立 revision 信封；Android 统一经 `loadDocument/saveDocument` 保存到按 key 命名的独立数据库。旧 `loadState/saveState`、默认旧数据库连接和前端特殊路由均已移除。

旧 `lingonest.local.v1`／`lingonest-state.db`、旧闯关文档和旧删除计划不被读取、迁移或合并。旧安装的数据需要重新建立。重构没有批量删除历史文件，旧文件也不会成为新目录的来源；用户配置等其他独立服务不参与本轮数据重建。

## 2. 公共目录与默认教材

[CatalogState](../packages/learning-modes/catalog-state.ts) 拥有纯公共 schema；拒绝将事件、题库、教学状态或发布包写入该文档。校验包括身份、昵称、图片引用、课程数量、归档和学习指定关系。公共教材不使用七步的段落解析或重点词汇规则。

[公共目录服务](../src/application/catalog.ts) 负责所有公共变更。新建教材只写公共文档，不为七步创建草稿。孩子改名、选择、课程指定及归档也只写公共文档。归档会清除相关学习指定，恢复不会自动重新指定。

内置教材原文、标题和图片来自独立的 [starter.ts](../packages/materials/starter.ts)。七步从该公共原文构造自己的话轮与翻译，框架无需导入七步课程包来取得教材。公共目录不持有七步翻译、阶段或题目。

## 3. 教学内容中的原文是来源快照

七步内容记录可以包含本模式准备和审核采用的原文及图片。这些字段是教学来源快照，不能独立替换公共教材。保存时重新读取公共目录，并核对来源字段、课程存活状态和删除计划，再写七步文档。

共同教材修改采用单文档提交，不在同一操作中分别覆盖两个模式：

- 未发布七步内容的来源与当前教材不同，工作区投影回原文确认步骤，生成包与配方不再被采用；词汇保留为待家长重新确认的候选。
- 旧七步草稿不能重新覆盖已更新的公共原文。
- 闯关保存／发布仍校验来源修订及完整原文快照，过期候选不能发布。
- 已有任一模式发布时，共同教材保持只读。准备另一模式不改变已经发布的材料依据。
- 七步快照不保存公共归档时间；显示归档状态时由当前公共目录投影，归档后的历史仍可读。

由此避免“公共原文已更新、模式文档第二次写入失败”的部分提交。模式保存成功也不修改公共目录的 revision。

## 4. 运行上下文与故障边界

公共目录提供读取、只读快照投影、订阅及选择端口。七步和闯关均从公共目录获得孩子和课程，写入前刷新选择并核对排队命令的原上下文。公共选择改变时解除旧活跃会话，保留旧恢复点，回到新上下文的学习首页。

七步写入还校验工作区指定课程、教学包版本与模式；报告／确认页指定的课程可能不同于孩子当前选课，不能只用当前选课检查删除状态。公共订阅同时响应目录和删除计划，计划落盘即隐藏受封锁的孩子、课程及指定关系。

框架调用 `readOverview(learnerId, materials)`，向两个模式提供同一份经过删除封锁投影的公共教材范围。概况适配器只读取本模式文档，不自行加载公共存储；状态、记录、待办和资源均限定在宿主提供的范围内。作答详情按孩子、模式和记录 ID 从最新概况解析，切换孩子或删除记录后不会保留旧详情。

应用启动只要求公共目录与删除协调状态可读，不要求七步或闯关文档成功解码。查询发布情况失败时，公共目录仍可以查看，档案和新教材仍可管理；无法确认是否已经用于发布的教材暂时只读。错误不会用空数据覆盖损坏的模式文档。

七步文档损坏时，框架及闯关仍能运行。公共目录本身损坏则显示公共读取错误，保留原文档；独立存储不意味着可以凭空恢复损坏的公共身份。

## 5. 删除由三个所有者参与

[服务组合根](../src/application/services.ts) 注册七步、闯关和公共目录三个删除参与者。先收集全部资源并持久化计划，再依次清理教学数据和公共身份。公共课程是否可以彻底删除，由公共目录依据归档及内置状态校验；模式只解释自己的内容和资源。

任一步写入失败均保留计划，目标继续被屏蔽。两个模式已经清理、公共目录尚未成功保存时，下次启动接续公共清理；不重新开放该目标，也不提前删除文件。全部数据清理完成后，根据所有存活引用决定是否释放资源。

恢复会逐项处理所有删除计划；一项失败不阻止其他独立任务完成，失败项继续保留封锁与进度。公共框架负责展示待恢复数量和错误，支持在任一学习模式下重试；成功重试清除旧错误。页面发起删除失败时也会刷新公共范围，以反映已经提交的部分清理。

公共目录参与图片存活引用查询。因此两门尚未准备教学内容的教材共用一张图片时，删除其中一门也会保留另一门使用的文件。七步和闯关仍分别保护自己发布、候选及历史来源中的资源。

原先七步内部的 `pendingDeletions/pendingCourseDeletions`、课程指定、孩子数组和旧版本迁移已删除；统一删除文档承担恢复任务。

## 6. 模块入口与约束

| 入口 | 职责 |
| --- | --- |
| [catalog-state.ts](../packages/learning-modes/catalog-state.ts)、[catalog.ts](../packages/learning-modes/catalog.ts) | 公共数据 codec 与访问端口 |
| [application/catalog.ts](../src/application/catalog.ts) | 公共管理、来源修订、归档与公共删除参与者 |
| [application/services.ts](../src/application/services.ts) | 装配各状态所有者、应用队列和删除协调 |
| [seven-step/services.ts](../src/modes/seven-step/services.ts) | 将公共教材投影为本模式准备视图，校验七步内容保存 |
| [seven-step/state.ts](../packages/learning-modes/seven-step/state.ts) | 仅保存七步教学载荷 |
| [snapshot-repository.ts](../src/platform/snapshot-repository.ts) | 不区分模式的统一持久化机制 |
| [NativeDocumentStore.java](../android/app/src/main/java/cn/lingonest/app/NativeDocumentStore.java) | Android 文档 key 与数据库文件的隔离 |

原 `legacy-catalog.ts`、`legacy-data.ts` 及七步公共目录兼容门面已移除。应用组合根仍显式装配已安装模式的数据适配器，以便目录查询和删除协调在 UI 未挂载时继续工作；这不赋予模式公共数据所有权。

模式通过框架注入或显式参数取得服务，不能自行创建应用组合根。删除断言由平台提供；模式适配器不导入公共目录实现或公共存储 codec。拆分后的隔离与恢复复审见[循环复审记录](../issues/00048_20261024155309_公共数据拆分隔离与删除恢复循环复审.md)。

宿主连接、入口能力、全局模式只读视图、概况边界校验及刷新失败语义，统一遵循[框架与双教学模式接口契约](00026_20261024162351_框架与双教学模式接口契约.md)。
