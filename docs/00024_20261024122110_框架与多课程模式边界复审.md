## 1. 设计判断

继续采用“一套应用框架、同一份课程教材、各模式独立内容与学习状态”的结构。两种教学核心不需要统一阶段、题型、评分或复习算法；共享课程身份也不意味着共享发布状态或学习进度。

本轮确认的问题集中在写入权限、工作区上下文、读取失败和历史查询边界，已落实到代码。公共数据继续通过应用持有的兼容适配器访问历史快照，避免引入第二份可编辑目录。物理存储仍共用旧七步容器；本文不将其描述为已经完成独立存储迁移。

| 对象或行为 | 负责方 | 当前约束 |
| --- | --- | --- |
| 孩子、课程身份与指定关系 | 应用目录 | 模式使用相同 ID，不复制另一套档案或课程 |
| 标题、教材信息、原文、原图、补充图片 | 应用教材编辑器 | 各模式取材；模式保存不能替换这些公共字段 |
| 重点词汇、题库、生成草稿与发布 | 各模式 | 保存前核对教材；生成和审核规则保持独立 |
| 全局学习模式 | 应用设置 | 影响孩子学习；家长准备非当前模式不改变该选择 |
| 准备、报告和确认的模式／课程 | 当前工作区 | 跟随请求方上下文，不借用全局模式或孩子当前课程 |
| 历史内容与归档 | 模式解释、应用承载 | 归档后仍可读历史；归档课程不可开始学习；失效的指定查询不回退到其他课程 |
| 保存、读取和删除协调 | 平台机制与数据适配器 | 文档 revision、快照队列和应用队列承担不同职责 |

## 2. 教材只有一个写入所有者

公共教材字段由 [legacy-catalog.ts](../src/application/catalog.ts) 的目录命令管理。应用服务启用共享教材约束后，[legacy-data.ts](../src/application/services.ts) 的七步保存端口先比较已提交教材字段，再允许修改教学字段。比较在原有应用队列和快照更新内进行。

这使两类旧写入都不能覆盖公共教材：

- 家长在教材页保存新原文后，旧七步草稿不能把旧原文和生成包重新写回。
- 闯关已发布、七步仍在准备时，七步保存不能绕过公共教材的发布冻结规则修改原文或图片。

词汇表图片同样是共同教材资源。图片添加、排序、旋转和移除集中在共同教材编辑器；七步负责识别这些图片、整理词条和确认重点词汇。七步工作区提供返回教材编辑的入口，避免出现两个可以各自修改同一图片列表的入口。

共同教材变化后，未发布的七步生成内容失效，需要重新确认；闯关候选发布前仍核对完整教材快照。已发布内容绑定的材料继续保持原版本。重新进入准备页时读取最新教材，已经完成离页保存的编辑器不再追加一次后台保存。

## 3. 学习选择和家长工作区分别绑定

[ApplicationFrame.vue](../src/application/ApplicationFrame.vue) 保存全局学习选择，也保存当前插件工作区的模式、课程和表面。两者用途不同：

- 学习页使用全局启用模式，以及当前孩子指定的课程。
- 家长准备、报告和确认使用打开该工作区时指定的模式与课程。
- 插件通过 `openParent(surface)` 请求导航时，沿用该插件的模式和课程；只有没有指定课程的学习工作区才取孩子当前课程。
- 设置中的实际模式切换继续先保存、后提交全局选择；单纯准备其他模式不调用切换。

契约说明见 [workspace.ts](../src/application/workspace.ts)。第三模式夹具验证了未启用模式在另一门课程中请求准备导航时，仍留在自己的上下文，孩子的全局模式保持原选择。

## 4. 三层持久化职责

| 机制 | 保证 | 不承担的职责 |
| --- | --- | --- |
| `SnapshotRepository` | 原生／浏览器路由、codec、容量与 revision 校验 | 不解释教学状态，不协调多个文档的业务事务 |
| `SharedSnapshot` | 同一实例的读取、异步更新及发布使用同一序列；写入前读取最新提交值 | 不替代跨实例 revision 校验，不允许更新回调等待同一实例的另一项排队操作 |
| `MutationQueue` 与删除协调器 | 应用变更顺序、跨文档删除计划、存活引用和失败接续 | 不解释模式的教学载荷 |

此前只有更新排队，独立刷新可以插入异步更新中间并返回旧状态。现在刷新和更新使用同一快照队列；更新内部调用不再次排队的私有读取，避免自我等待。失败不会将未提交修改发布给订阅方，后续操作可以继续排队。

初始化只缓存成功或正在进行的读取。共享快照、闯关存储和应用兼容数据启动读取失败时，释放失败的初始化 Promise，允许重试；重试仍走原 codec，不用空数据覆盖损坏内容。

## 5. 故障和历史访问

闯关文档损坏不应让公共目录整体无法读取。查询其他模式发布状态失败时，目录仍返回教材和档案，将无法确认可编辑性的教材设为只读，并提供明确原因。教材更新和跨模式彻底删除仍需要实际核对相关数据，不能因读失败而放行；损坏文档保持原字节。

七步报告按指定课程查询时包含已归档记录，学习选择则继续只使用未归档课程。归档状态不删除历史内容，也不开放学习。若指定历史课程已经不存在，返回该课程身份下的不可用状态、空题目和空图片，不用内置课程替代。

## 6. 新增模式与兼容范围

当前是随应用注册和发布的静态教学插件体系。接入新模式需要同时完成：

1. 实现独立教学核心、codec、生成审核与历史解释；核心不导入其他模式、Vue 或应用服务。
2. 在 [registry.ts](../src/modes/registry.ts) 注册工作区和只读概况；使用框架提供的导航、家长确认及设备服务。
3. 在 [services.ts](../src/application/services.ts) 的组合根接入独立存储、共享变更队列、发布状态查询和删除参与者。
4. 声明自己的资源清单和存活引用，验证归档、永久删除、模式切换及保存失败后恢复。

仅增加一个 UI 注册项不等于完成有持久数据的新模式接入。未实现动态插件安装或移除，不能在保留数据时直接删掉其维护适配器。

旧七步容器的解码仍是公共目录的兼容前提，损坏该共同容器时公共数据也不能可靠读取。完整物理拆分需要另行设计版本迁移、删除任务接续、失败恢复及旧安装兼容；本轮通过应用所有权和保存端口约束修复现有行为，保留现有存储格式。
