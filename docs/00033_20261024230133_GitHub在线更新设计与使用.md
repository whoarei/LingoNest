# GitHub 在线更新设计与使用

建立时间：2026-10-24 23:01:33（Asia/Shanghai）。承接[GitHub 发布链路](00031_20261024215010_GitHub持续集成与Android发布.md)，本轮在当前源码中实现在线更新，未递增应用版本、创建标签或远程发布。验证范围见[实现验证](../issues/00055_20261024230133_在线更新实现与验证.md)。

## 公共入口与提醒

- 学生、家长均可从顶部“更多 → 应用更新”进入独立更新页，无需家长算式；家长的模型密钥、课程管理设置保持原有入口。进入及安装前复用应用框架的保存、停止播放和任务检查，保存失败阻止后续操作。
- 应用挂载后独立执行版本检查，不等待网络结果才展示首页或开始学习。成功检查后 24 小时内不重复自动检查，失败后退避 15 分钟；手动检查不受这两个时间限制。恢复前台不自动再次检查。
- 发现兼容的新版本时，仅在未进入专注练习、没有确认对话框且应用空闲的学习首页显示提示。结果在练习中返回时保留，退出后再展示，不改变当前页面或焦点。
- “稍后”按构建号记录 24 小时提醒抑制，新构建不沿用旧构建的抑制。检查及提醒计划是设备级状态，不随孩子或教学模式切换。
- 自动检查失败不显示全局错误；手动检查失败在更新页展示原因。浏览器预览不发起更新请求，测试签名版本不能下载安装正式更新。

## 更新协议和 CI

固定清单入口为 `https://github.com/whoarei/LingoNest/releases/latest/download/update.json`。使用 GitHub 发布文件重定向，无需应用持有令牌或调用 REST API。当前已发布的 `0.1.16` 没有该文件，返回 404 时明确提示“当前发布尚未提供在线更新清单”，不能误报为最新版本。

清单格式 1：`schemaVersion`、`applicationId`、`versionName`、`versionCode`、`minSdkVersion`、`apkUrl`、`size`、`sha256`、`notes`、`publishedAt`。`versionCode` 为比较依据；`versionName` 只展示。清单至多 64 KiB，说明至多 16000 字符，APK 至多 200 MiB。说明按文本展示，不执行 HTML。

[生成脚本](../scripts/generate-update-manifest.mjs)从包版本、锁文件、Android 构建号／最低 SDK、归档版本说明与真实 APK 字节生成清单，校验标签和版本一致性。`publishedAt` 表示本次生成时间，GitHub 公开发布时间稍晚于此。APK 地址固定为本仓库对应标签下的 `lingonest-<版本>-release.apk`。

[发布工作流](../.github/workflows/release.yml)在完成现有正式签名、包身份与内容检查后生成清单，将 `update.json` 一并加入 `SHA256SUMS.txt`；最终作业复核校验文件，上传所有资源到草稿 Release，再公开并设为 latest。继续拒绝覆盖已经公开的同版本发布。

发布作业使用仓库级串行队列。公开之前读取当前 latest 所在标签的 Android 源码，要求新版本名与构建号均严格递增；网络或元数据异常时停止发布，避免不同标签的构建交错完成后把 latest 指回旧版本。旧 `0.1.16` 没有清单时同样可以从标签源码核对构建号。该 REST API 查询只发生在 CI，应用端仍直接读取清单。相关规则见 [GitHub 并发控制](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency)。

## Android 下载与安装

[原生插件](../android/app/src/main/java/cn/lingonest/app/AppUpdatePlugin.java)负责检查、下载、缓存复用和打开系统安装界面。前端不能指定任意 URL 或路径，只提交已经核对的目标构建号。原生层使用自己的清单缓存重新核对构建号。

1. 仅接受包名 `cn.lingonest.app`、非 debuggable 且证书指纹为现有发布证书的当前安装。新 APK 也必须满足该要求。证书 SHA-256 固定为 `28c461e4f2f8612f9d7717d727e772177474798fd7c48b03ca3ffbca8c81bf0a`，不信任远程清单提供的任意证书。
2. 限定 HTTPS、本仓库版本化发布路径以及 GitHub 产物域名；逐跳校验重定向，最多五次跳转，设置连接／读取超时和清单读取上限。不接受任意镜像、HTTP 降级、用户信息或非标准端口。
3. 下载前检查可用空间。流式下载限制大小、报告进度，核对长度与 SHA-256，解析 APK 检查真实包名、构建号、版本名、设备兼容性和证书。系统安装器继续负责完整 APK 签名验证。
4. 安装文件位于缓存 `app-updates/`，未完成文件使用 `update.pending.apk`；失败或取消时删除本次临时文件，已验证包可再次校验后复用。重试时先删除上次进程退出留下的临时包和不可复用的旧安装包，再判断空间，避免这些文件阻塞重新下载。应用数据、课程音频和录音不在该目录，更新模块不清理这些数据。
5. 下载及安装分别由用户点击；安装前调用应用框架保存流程，再重新校验 APK。Android 8+ 未授权安装来源时显示授权入口，用户返回后仍需再次点击安装。通过只读 FileProvider URI 交给系统安装器，不要求外部存储权限，不自动确认系统安装。
6. “系统安装界面已打开”仅代表安装器启动。取消后可以重试，实际升级结果由新进程读取当前安装版本确认。没有后台服务、差分包或断点续传，不保证进程在后台被回收后仍继续下载。

安装准备期间，页面按钮和 Android 返回键都不能离开更新页，避免已保存后又开始新的练习再被安装器打断。从教材编辑页进入更新时先保存，返回时恢复编辑状态。原生清单缓存丢失后不沿用前端的成功检查节流，而是重新检测。

## 首次接入和发布边界

现有 `0.1.16` 尚无在线更新代码，用户必须手动覆盖安装一次携带本功能的正式签名新版本；从该版本开始通过应用内更新。首次对外发布仍需按原发布步骤递增版本和构建号、补充版本说明并推送标签，不能重新发布 `v0.1.16`。

原 Debug 安装与正式发布证书不兼容，在线更新不绕过 Android 签名规则，也不自动卸载旧应用。应用数据格式变化依旧需要独立设计迁移、兼容和验证，覆盖安装本身不能解决旧快照不迁移问题。
