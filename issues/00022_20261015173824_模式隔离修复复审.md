## 2. 问题

### [P2] 播放权准备完成后发生卸载，仍会启动设备播放

位置：[speech.ts](../src/platform/speech.ts)，151–158 行；浏览器分支同样存在于 176–190 行。

`beginPlayback()` 是异步函数，它先取得所有权并设置 `phase = "playing"`，调用者再通过 `await` 等待结果。这个等待会让 Vue 已排队的更新或卸载先执行。若卸载发生在这里，清理函数会停止设备、撤销所有权并增加 sequence，但调用者恢复后没有重新检查 disposed 或 token，仍执行 `native.playCourseAudio()`、`native.speak()` 或浏览器的 `speechSynthesis.speak()`。

复现使用真实 Vue effectScope 和 `flush: "post"` 的 phase 观察器，在播放状态更新时销毁作用域；没有修改被测源码。结果为：

```text
原生：stop → play，playingAfterDispose = true
浏览器：cancel → cancel → speak，scopeActive = false，playingAfterDispose = true
```

因此，不仅迟到的响应需要失效，实际设备调用前也必须重新验证仍然有效。否则卸载时的停止发生得过早，后续播放没有存活的所有者负责终止；浏览器的待播放 Promise 也可能继续等待已经错过的取消过程。

建议消除“校验/取得所有权”和实际设备启动之间的未保护等待，或在每个等待恢复后重新校验请求和作用域，并正确释放属于本请求的预留所有权。补充卸载发生在播放启动之前的微任务边界测试。

证据：[原生复现](../artifacts/mode-fix-review-native.test.ts)、[浏览器复现](../artifacts/mode-fix-review-browser.test.ts)、[原生结果](../artifacts/seven-step-fix-review-races.json)、[浏览器结果](../artifacts/seven-step-fix-review-browser.json)。现有卸载测试等待 native 调用已发生后才销毁作用域，未覆盖这个间隙。

### [P2] 已卸载的生成请求会停止另一实例的播放

位置：[speech.ts](../src/platform/speech.ts)，262–265 行。

`generateCourse()` 在等待 `stop()` 和 `generationStopping` 之后，先调用全局 `stopDevicePlayback()`，然后才检查 disposed 和 courseEpoch。此时调用者可能已经卸载，但仍能停止当前媒体所有者。

复现步骤：

1. 控制器 B 已在播放，确认设备处于 playing。
2. 空闲控制器 A 调用 `generateCourse()`，进入第一次 await。
3. 立即销毁 A 的作用域，随后等待生成请求结束。

结果：生成返回 false、原生生成调用为 0，但 B 已停止，`stopSpeech` 被调用一次。它不会破坏持久数据，却会在错误回退或后续模式交接时打断仍存活的媒体实例，与本次所有权修复目标不符。

建议在任何跨实例设备操作之前重新校验调用者，尤其是每次 await 恢复之后。现有“同步卸载不启动生成”测试只检查 generateCourseAudio 没有执行，没有同时保留另一个活动播放器。

证据同[原生复现及结果](../artifacts/mode-fix-review-native.test.ts)，观测结果位于[结果 JSON](../artifacts/seven-step-fix-review-races.json)的第二项。

### [P2] no-flex-gap 回退选择器不再匹配，旧版 WebView 间距回退失效

位置：[style.css](../src/modes/seven-step/style.css)，2634–2638 行及同类回退；标记设置在 [Experience.vue](../src/modes/seven-step/Experience.vue)，146–150 行。

特性检测仍把 `no-flex-gap` 加在 `document.documentElement`，即七步根节点的祖先上。修复却将原 `.no-flex-gap .brand-symbol` 改为 `.seven-step-mode .no-flex-gap .brand-symbol`，要求标记位于七步根节点内部。这两个层级互相矛盾，整个同类回退段都无法匹配。

在真实 Edge 中模拟“不支持 flex gap”的检测结果，并关闭对应 gap 以检验回退：390px 和 1280px 两种宽度下，当前品牌按钮右边距均为 0px；同一 DOM 替换成 Git HEAD 原样式后均为 11px。原选择器可匹配，新选择器不可匹配。

这不是跨模式样式污染复发，而是作用域改写引入的布局兼容回归。不支持 flex gap 的旧 WebView 会丢失按钮、资料、练习选项及其他回退间距。建议把检测标记归属到模式根，并让选择器同时匹配根节点上的模式类和能力类，或在保留正确祖先关系的前提下约束七步目标。补充能力检测为不支持时的布局断言。

证据：[浏览器复现脚本](../artifacts/review-mode-fix-style.mjs)、[两种宽度的新旧计算样式](../artifacts/seven-step-fix-review-style.json)。这是现代浏览器中对能力分支的模拟，不是实测旧版 Android WebView。

现有 CSSOM 测试检查选择器是否以模式类开头，不能判断祖先关系是否正确；原样式差分脚本只确认机械加前缀后的声明和顺序一致，也不能据此证明旧布局语义不变。
