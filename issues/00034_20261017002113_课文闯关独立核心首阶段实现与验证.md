## 1. 本次实现范围

完成方案第一阶段的独立核心与自动化验证。新增 [passage-path](../packages/learning-modes/passage-path/index.ts)，不修改七步核心、公共契约、应用页面、原生代码或正式注册表。设置中仍仅提供七步学习。

## 2. 已落地的运行规则

默认常规轮 8 题，候选不足时最低 6 题；每关通常最多 2 个新知识块。优先保留新目标的理解题及声明需要的无选项回想题，之后穿插到期与薄弱目标。没有复习历史时使用本关巩固，不导入未学内容。每轮跨课常规题最多 2 题。

实际题目、来源包、选项与词块顺序、随机种子、当前位置、未提交输入和反馈全部持久化。恢复不重新抽题。更换孩子或课程保留各自会话，旧会话命令不能以新上下文提交。

错误保持真实记录，最多追加 2 道未出现过的同目标补练，每个目标一轮最多补练一次。无变体则留到后续轮次。即使全错，完成有限题序后也可推进路径；路径完成不被解释为知识掌握。

首轮作为基线诊断，不产生稳定表现证据。初始评价版本要求至少 3 个相隔不小于 24 小时的独立成功轮次才能显示稳定；需要回想的目标还要求无选项作答。提示、查看原文、同目标反馈之后的作答、错误补练及异常时钟不作为独立证据。当前查看原文按整轮可能暴露处理，来源精确映射留待公共材料端口接入。

初始复习间隔随有效独立轮次采用 24、72、168 小时，错误或需辅助的练习采用较短的 4 小时安排。已取得本轮独立证据后的正常反馈不会将其较长间隔重置。以上为版本 1 的试用策略，尚未经实际学习效果评估。它们属于新模式，未改变七步评价。

运行上下文由调用方提供时钟可信标记，并在核心额外检查回拨。异常时间原样留在作答事实，但不推进可信时钟、不生成独立证据，也不把复习推迟到异常的未来日期。正式界面仍需接入设备时钟监测能力。

## 3. 发布 资源与兼容边界

候选与发布分开，显式采用时检查审核时间与必需音频清单。音频包含原文及题目需要的文本，按规范化文本去重，分别提供话轮和题目到实际资源 ID 的映射。资源版本带模式、实例和包修订，保持真实课程 ID，不覆盖七步的资源版本。清单数量、标识长度和文字预算按现有 Android 音频接口约束校验。

重新生成可保留原发布包；采用新的包修订时保留旧包及历史作答，从新路径开始，封存所有引用旧包的活跃会话，包括其他课程中的混练会话。同修订不可替换内容。草稿编辑和采用操作的页面确认不属于本阶段。

独立 key 为 `lingonest.passage-path.v1`，复用 `SnapshotRepository` 默认文档存储机制。新模式自己的事件、队列和路径在同一快照内保存。共享档案与教材仍由七步历史快照管理；本阶段没有创建第二套课程库，没有迁移、修改或清理历史数据。

`RuntimeContext` 的课程可用性、当前模式、孩子和资源状态是后续宿主必须提供的可信输入；核心会检查这些输入，但尚未实现真实共享目录、文件检查和页面绑定。正式注册前必须完成方案第二、三阶段，尤其是共享写入和跨模式删除协调，不能因核心可运行就向孩子开放入口。

## 4. 正式回归测试

新增 3 个测试文件，共 42 项测试，另有共享测试夹具 [passage-path.ts](../tests/fixtures/passage-path.ts)。夹具使用现有“一起加入运动队”的原文及两组人工编写的候选目标，不作为应用内置课程安装。

|---|---|
| [passage-path-authoring.test.ts](../tests/passage-path-authoring.test.ts) | 来源解析、模型端口与输入快照、编译可重现、非法引用、重复 ID 和重复题面、答案歧义、听辨缺音频、提前复习、回想覆盖、候选不足、音频去重和原生标识边界 |
| [passage-path-runtime.test.ts](../tests/passage-path-runtime.test.ts) | 实际队列恢复、输入与反馈、幂等、全错与补练上限、路径完成后的巩固、重练、身份与课程隔离、切换后填空输入恢复、异常时间、独立证据、缺内容及音频拦截、新包采用与跨课引用封存、损坏快照与历史评分保护 |
| [passage-path-storage.test.ts](../tests/passage-path-storage.test.ts) | 独立快照、七步原字节保留、并发提交与继续去重、保存失败不推进、revision 冲突、排队期间切孩子、未知版本保护、核心依赖边界和正式注册表仍仅七步 |

运行器用例对 50 个不同随机种子检查所有新目标都先理解再回想、必要覆盖不丢失、全错时仍有限结束、快照可恢复及原始输入状态不被修改。不是只断言某一条固定题序。

执行结果：

- `npm test`：14 个文件、146 项全部通过，包含原有 104 项回归和新增 42 项。
- `npm run build`：通过，含 `vue-tsc --noEmit`、生产构建以及构建前后的无预生成音频检查。
- 现有七步兼容回归继续核对原课程与题目 ID、音频规格摘要、学习投影摘要、旧档案、未完成恢复点及跨孩子隔离；新模式存储用例直接比较七步存储的原始字符串未变化。

本阶段未调用真实模型或 TTS 服务，未新增真实模式页面，未执行本轮 Playwright、真机升级或安装验证。通过核心测试不能替代第二模式完整接入后的端到端与设备兼容验收。

## 5. 后续工作

按方案第二阶段接入公共材料与档案端口，由七步边界内的兼容适配器解释旧格式。七步与新模式的共享管理操作需要统一写入协调，彻底删除需要可恢复的跨模式计划及资源引用检查。

之后接孩子路径、练习与原文页面，以及家长生成、全部候选审核和新包采用页面。生命周期、样式隔离和旧 WebView 间距回退在真实两个体验间验证，通过后才加入通用设置的正式模式列表。
