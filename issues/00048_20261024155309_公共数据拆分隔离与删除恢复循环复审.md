# 公共数据拆分隔离与删除恢复循环复审

本轮继续审查公共目录拆分后的框架、七步与课文闯关边界。用户已允许放弃旧数据兼容，本轮没有恢复旧容器适配，也没有读取或迁移旧安装数据。

## 已修复问题

| 问题 | 可复现场景与影响 | 修复 |
| --- | --- | --- |
| 删除恢复被首项故障阻断 | 两门课程均因资源删除失败留下计划；重启后第一门仍失败，第二门即使已可恢复也不会执行 | 逐项恢复全部计划，保留每项完成进度，最后汇总仍失败的任务 |
| 七步排队写入未校验工作区课程 | 当前指定课程为 A，报告工作区指定 B；排队期间 B 归档或工作区切回 A，旧 B 的接触事件仍能写入 | 在提交前同时核对孩子选择、工作区实际课程、包版本、模式和公共可用状态；使用工作区课程检查删除标记 |
| 公共订阅未反映删除封锁 | 删除计划已落盘，七步文档清理失败，公共目录尚未变化；订阅方仍收到原来的孩子和选择 | 目录订阅同时响应目录与删除文档，并统一投影封锁范围 |
| 跨孩子保留作答详情 | 查看甲的作答后，持久化选择变为乙，进入设置再返回仍显示甲的详情 | 仅保存孩子、模式和记录 ID，从当前概况重新解析详情；范围失效时返回记录列表 |
| 模式概况绕过公共删除范围 | 删除已启动，但模式仍有未清理的内容；七步自行读取公共文档，闯关直接返回所有内容 | 框架把同一份公共教材范围传给两个概况接口；模式仅读取自己的教学数据，按宿主范围投影状态、记录、待办和资源 |
| 删除中断后列表仍显示旧目标 | 彻底删除失败时，公共页只显示异常，没有刷新部分提交后的目录 | 失败后重新读取公共范围与工作区，删除中的对象不再以可恢复对象出现 |
| 恢复反馈依赖七步且旧错误残留 | 闯关模式下启动恢复失败缺少公共状态；稍后成功重试，七步启动错误仍保留 | 组合根提供通用的待恢复数量与错误，框架设置负责展示；成功重试清除错误 |
| 模式反向依赖应用装配 | 七步控制器能自行创建完整应用服务，还从公共目录实现中取得删除断言和复制辅助函数 | 七步显式接受框架注入的服务；删除断言归平台；模式不再导入组合根、公共目录实现或公共存储 codec |

## 回归与复审

- 新增 `tests/public-data-review.test.ts`：独立删除计划继续恢复、错误清除、七步指定课程归档与范围变化、跨孩子删除中断恢复、删除封锁通知、双模式概况范围。
- 新增 `tests/e2e/public-data-review.spec.ts`：跨孩子详情隔离、删除失败后的列表与记录刷新、闯关模式下公共重试状态。
- 模块边界断言覆盖整个 `src/modes/`，禁止反向导入应用装配、公共目录实现和公共 codec。
- 既有用例继续覆盖两个教学模式的过期选择写入、跨课程混练删除、其他孩子的记录保留、共享图片保留、归档与恢复、删除计划和各参与者提交失败、资源清理失败及重启接续。

## 最后一轮复审结论

重新检查公共教材编辑、模式概况、排队事务、删除参与者、存活资源引用和失败后页面刷新。公共变更不写教学文档；模式写入不能替换共同教材；归档保留历史但清除学习指定，恢复后需重新指定；彻底删除以持久化计划封锁目标并逐阶段恢复。没有再发现值得修复的框架耦合、跨课程／跨孩子数据隔离或删除恢复问题。

本轮未改动 Android 原生代码；界面测试使用 Edge 和受控原生接口夹具，不代表真机录音或真实模型服务验收。
