# 双教学模式与框架接口循环审查修复验证

本轮以七步、课文闯关和公共框架之间的接口为范围，在上一轮公共数据拆分基线上继续审查；不改变两种模式各自的教学规则。

## 问题与修复

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 全局模式控制器直接提供给教学组件 | 模式可以调用全局切换和离页钩子命令，职责超出只读需要 | 提供不可变的 `ModeSelectionView`；完整控制器由框架保存并显式传给公共设置 |
| 宿主回调未绑定组件生命期 | 卸载后的模式仍可保留导航、通知或连接方法，作用于替换它的工作区 | 每次挂载／重试建立独立桥接，卸载后使回调及连接失效，隐藏工作区禁止主动导航 |
| 家长确认 Promise 提前结束 | 调用方等待到的是弹框出现，无法等待取消或动作完成；旧范围动作可能延迟执行 | 等待最终决定和动作执行；取消时释放等待；执行前复核工作区范围和激活序号 |
| 确认入口能力来自概况的 `canConfirm` | 静态能力依赖数据读取，框架还把确认文案硬编码为七步口语语义 | 注册声明支持的入口与确认文案，导航再次校验，闯关不再接收确认入口 |
| 启动错误缺少统一恢复协议 | 七步读取失败后停留在加载状态，闯关使用自己的重试，宿主无法一致处理 | 适配器提供 `loadError`，宿主创建统一重读入口，重试建立新连接并保留原文档 |
| 概况结果未在框架边界检查 | 错误类型、重复记录或越界课程可能破坏公共页面；共享输入对象可互相影响 | 独立复制输入与输出，验证结构、标识、时间、课程范围、计数和资源清单，错误按模式隔离 |
| 两种模式的 `refresh` 语义不同 | 七步仅更新时间和音频，依赖目录查询顺带刷新；闯关重读异常会阻止进入公共页面 | 七步显式重读自身数据；宿主隔离刷新读取失败；保存失败仍阻止离页 |
| 全局模式控制器保留失败的初始化 Promise | 修复模式设置文档后，原控制器仍会返回首次失败，无法原地恢复 | 首次读取失败后释放缓存；公共设置提供重新读取应用数据入口 |

## 循环审查与复现

1. 静态审查注册、宿主、工作区和服务接口，修复权限暴露、生命周期和入口能力问题。
2. 加入桥接范围变化、异步确认、适配器替换和只读视图回归；真实工作区夹具验证卸载后的回调失效、确认等待及模式自定义文案。
3. 复审概况查询边界，加入对象隔离及错误结果回归，并验证一个模式返回错误概况时其他模式与公共档案仍可访问。
4. 继续复审刷新失败路径，复现闯关启动后快照损坏、点击“课程”仍留在原页面的问题。修改宿主后相同场景通过，且损坏文档字节保留。
5. 为七步增加独立刷新端口回归，证明不调用目录概况也能读取外部已经提交的学习记录，且纯刷新不增加持久化 revision。
6. 最后一轮复审补充全局模式控制器的失败重试，单元和界面回归均验证修复文档后能够从公共设置重新初始化，且修复后的文档 revision 保持不变。

## 最后一轮复审结论

再次检查注册声明、工作区连接和回调失效、确认等待、概况输入／输出范围、保存与刷新错误处理、全局控制器重试，以及两种模式各自的服务端口。保留一套公共框架与两个独立教学核心的结构合理；本轮收紧接口权限和生命期，明确能力与错误语义，没有再发现值得修复的接口问题。设计文档已描述当前实现，未把未来分插槽设想或旧公共存储迁移作为本轮待办。

本轮未修改 Android 原生代码。界面测试为 Edge 加受控原生接口夹具，不将其视作真机或真实模型验收。

当前设计以[框架与双教学模式接口契约](../docs/00026_20261024162351_框架与双教学模式接口契约.md)为准；早期设计文档和开发指南已同步更新引用。
