## 2. [P2] 切换孩子或课程后，模式切换会清空旧恢复点

位置：[useLearning.ts](../src/modes/seven-step/useLearning.ts)，`prepareModeChange()` 第 357–358 行。

`clearRun()` 清空当前题队列、答案、选项及录音路径，却保留原 `sessionId`。随后 `selectLearner()` 或 `assignCourse()` 已切换上下文；新增加的切换准备逻辑只检查旧 ID 是否还存在于 `state.runs`，仍对该记录执行 `copyDraft()`，把空的当前界面状态写入不再活跃的旧恢复点。

已分别复现两条路径：

1. 加载固定旧快照，为档案甲完成 S1，恢复其已有 S2 练习，答案为 `fa`，提示等级为 1。
2. 退出练习到家长空间，等待保存完成；切换到档案乙，或改为学习内置课程。
3. 确认旧 S2 恢复点答案仍为 `fa`。
4. 执行模式切换；同一旧恢复点的 `answer` 被写成空字符串。课程、事件、提示等级未改变。

这会破坏“原模式进度保留”的承诺；同一保存函数也会覆盖旧选项及录音路径。应解绑已清空的活跃会话，或要求恢复点同时匹配当前有效练习、孩子与课程后才保存。回归应分别覆盖切换孩子和切换课程，然后切换模式并切回恢复。

## 3. [P2] 进入模式页先卸载编辑器，使草稿保存失败无法阻止切换

位置：[ParentSpace.vue](../src/modes/seven-step/components/ParentSpace.vue) 第 269 行；相关准备钩子位于 [CourseManager.vue](../src/modes/seven-step/components/CourseManager.vue) 第 145–151 行。

正常入口是先从“课程”导航到“模式”，然后选择模式。`CourseModeSettings` 与 `CourseManager` 属于互斥的条件分支，因此前一步已经卸载课程编辑器，同时注销它的 `beforeSwitch` 准备函数。原导航还会清空 `managedCourseId`；卸载保存是无等待的调用，其失败没有传递给导航或全局选择。真正执行模式切换时，编辑器的持久化检查已经不在准备集合中。

浏览器原生接口模拟下已复现：

1. 新建课程，保存标题“已保存课程”。
2. 设置学习快照保存失败，在编辑器把标题改为“未保存的家长修改”。
3. 点击底部“模式”，选择测试第二模式并完成家长确认。
4. 新模式成功挂载，持久化课程标题仍为“已保存课程”，未保存修改已丢失。进度保存失败没有阻止模式切换。

应在切换家长页签、清空课程 ID、卸载编辑器之前等待草稿保存，失败时保留原编辑器；也可以由上层持有未保存状态及对应准备函数，直到切换成功。回归必须从实际编辑页面进入模式页，不能只直接调用准备函数。
