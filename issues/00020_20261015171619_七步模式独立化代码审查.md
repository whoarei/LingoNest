## 1. 审查结论

七步模式的内容编译、评分、学习证据、复习、快照校验、报告和主要界面已拥有独立的代码归属；实际公共宿主、平台能力及原生存储中未发现七阶段解锁、能力掌握或选题算法残留。旧课程与学习进度兼容性检查未发现本次重构引入的回归。

但是，“完整独立”的验收暂不能通过：发现并复现两项 P2 隔离缺口，分别是模式卸载后原生播放未停止、七步全局样式未隔离。当前唯一模式的正常学习流程可通过测试，但这两项问题会影响模式卸载及后续模式共存，不能用常规测试通过来替代边界验证。

本次仅审查和记录，未修改业务代码，也未自动修复以下问题。

## 2. 发现的问题

### [P2] 模式作用域销毁后，已经启动的原生播放继续运行

位置：[src/platform/speech.ts](../src/platform/speech.ts)，262–269 行；模式宿主的错误回退见 [ModeHost.vue](../src/modes/ModeHost.vue)。

`onScopeDispose` 只标记 `disposed`、增加请求代次并移除事件监听，没有停止已经进入 `native.playCourseAudio()` 的播放，也没有取消浏览器 `speechSynthesis`。增加代次只能使迟到结果失效，无法终止已经启动的设备操作。

宿主遇到子界面异常时会卸载模式体验，此时音频可继续播放，而原来的停止按钮和状态监听已经消失；后续模式切换同样可能产生旧模式串音。七步运行服务和体验组件的卸载逻辑也没有补上这一停止过程。

隔离复现先让模拟原生播放器进入播放状态，再执行模式的 `effectScope.stop()`。观测结果为：

```json
{
  "playingAfterDispose": true,
  "stopSpeechCallsOnDispose": 0
}
```

证据：[复现用例](../artifacts/mode-review-lifecycle.test.ts)、[观测结果](../artifacts/seven-step-review-lifecycle.json)。命令 `npm test -- --config artifacts/mode-review-vitest.config.ts` 中，“卸载后播放已停止”的断言失败，复现成立；该用例位于隔离审查目录，不计入常规 70 项测试。

建议提供可等待的暂停/销毁过程，按设备资源所有权停止本实例正在进行的操作，再卸载页面；同时覆盖正在播放、配置加载中和监听注册迟到等情况。直接对所有控制器的卸载无条件调用全局停止，也可能打断另一个仍存活的音频控制器，需要明确所有权。

### [P2] 七步样式仍是全局选择器，卸载后会影响宿主及其他模式

位置：[src/modes/seven-step/style.css](../src/modes/seven-step/style.css)，1–27 行及 43–87 行；导入位置为 [Experience.vue](../src/modes/seven-step/Experience.vue) 的第 2 行。

样式虽然移到七步目录并改为懒加载，但仍直接修改 `:root`、`body`、`button`、`input`、`h1` 等全局元素。普通 CSS 导入不会随 Vue 组件卸载而撤回，因此代码位置变化没有形成样式作用域。

真实浏览器复现先记录无七步样式时的普通输入框，再加载实际应用、等待七步界面就绪、卸载 Vue 应用，并在原容器中放置不属于七步模式的输入框。观察到七步样式标签仍保留一个，且新输入框继续受到影响：

| 属性 | 未加载七步时 | 七步界面卸载后 |
|---|---|---|
| 字号 | 13.3333px | 16px |
| 圆角 | 0px | 12px |
| 文档背景 | 浏览器默认 | 七步主题的 `rgb(247, 246, 240)` |

证据：[浏览器复现脚本](../artifacts/review-mode-style.mjs)、[观测结果](../artifacts/seven-step-review-style.json)。这是样式隔离验收缺口；当前仅运行七步时外观保持原样，不属于旧课程数据迁移回归。

建议把真正通用的基础样式留在公共层，将七步主题、布局和控件外观限定到模式根节点，或使用可靠的样式隔离机制；补充加载、卸载并挂载另一种中性体验后的计算样式检查。现有依赖检查仅扫描 TS/Vue 导入及阶段字段，没有覆盖 CSS 的全局作用。

## 3. 公共层教学逻辑审查

| 范围 | 结论 |
|---|---|
| `src/App.vue`、`src/modes/ModeHost.vue`、模式注册表 | 不识别 S1～S7、题型、掌握算法；负责加载体验。样式和卸载生命周期仍有上述缺口 |
| `src/platform/content.ts` | 负责配置与传输，无七步提示词或题库编译 |
| `src/platform/snapshot-repository.ts` | 负责 codec 调用、容量、revision 和写入，无阶段或评分校验 |
| `src/platform/speech.ts`、共享音频/设置/图片控件 | 负责媒体与配置，无七阶段或选题算法；存在媒体卸载缺口 |
| Android `NativeStateStore`、`NativeGuards`、`CourseAudioSpec` | 通用 JSON/事务、路径及资源清单约束，没有七步学习算法；本次未改 Java |
| `packages/learning-modes/seven-step/` | 七步教材、草稿编译、状态 Schema、评分、证据、复习、报告均在模式内，不依赖 Vue 或应用实现 |

`src/useSpeech.ts` 的默认内置课、`src/style.css` 的七步样式导入，以及 `src/course*.ts`、`src/domain.ts`、旧 `packages/learning-engine/src/*` 仍是显式的历史兼容入口。它们继续绑定七步是已记录的兼容选择；实际公共宿主和共享控件没有通过这些入口执行七步教学逻辑。新模式应使用 `src/platform` 和模式契约，不能把旧兼容出口当成通用模式 API。
