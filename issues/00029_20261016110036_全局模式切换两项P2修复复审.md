## 2. 旧恢复点保护复审

- [useLearning.ts](../src/modes/seven-step/useLearning.ts) 将未启动或已退出的活跃会话明确表示为 `null`；`clearRun()` 解绑会话后才重置题目和答案。
- `savedRun()` 必须有活跃题队列，且保存记录与当前会话、孩子和课程一致。模式切换准备使用此检查；切换上下文后不会再把空界面写入旧记录。
- 开始或恢复练习时，仍从原 `PracticeRun` 恢复会话标识、题目索引、文本、选项、提示和录音路径；实际提交要求有有效会话，原事件及评分结构保持不变。
- 正式新增四条组合覆盖 S1 未提交选项、S2 旧文本与提示，分别在切换孩子或课程后切出/切回模式。期间七步快照逐字节一致，重新挂载并返回原上下文后，内容和进度恢复正确。

原先“旧答案 `fa` 被写为空字符串”和未提交选项丢失的路径已被正式测试阻止。

## 3. 草稿保存与卸载复审

- [Experience.vue](../src/modes/seven-step/Experience.vue) 先等待离开检查，成功后才清空编辑课程 ID 和切换页签。保存失败或待完成时，旧编辑器继续存在。
- [ParentSpace.vue](../src/modes/seven-step/components/ParentSpace.vue) 的页签由父组件控制，内部档案按钮等导航请求也进入同一检查，不能自行提前卸载编辑器。
- [CourseManager.vue](../src/modes/seven-step/components/CourseManager.vue) 复用模式切换和页面离开的准备函数；保存过程中若草稿修订号变化，继续保存最新版本，再允许离开。成功标记避免卸载时再次追加异步保存。
- 正式端到端用例覆盖真实编辑页 → 模式页、即时保存失败、重试、挂起保存、等待期间继续修改、其他导航被拦截，以及模式往返和重载后的草稿保留。它同时对比已有已发布课程、事件及恢复点。

额外审查探针覆盖“保存已挂起 → 系统返回与内部档案导航 → 延迟返回保存失败 → 重试”的组合：前两个导航被拦截；延迟失败后编辑器及最新修改保留，全局模式设置未变；重试成功后才进入模式页，旧课程、事件、恢复点与固定样本一致。此探针是补充证据，未计入正式测试数量；本机脚本和结果分别为 `artifacts/review-mode-fix-delayed-failure.mjs`、`artifacts/review-mode-fix-delayed-failure.json`。
