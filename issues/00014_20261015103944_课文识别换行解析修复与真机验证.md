## 真机排查

用户反馈点击“识别课文图片”后，原文框仍为空。在 2304FPN6DC（ADB `172.16.0.16:5555`）读取当前页面和公开配置后，发现原文长度为 0、未处于处理中，页面错误为“请先在设置中配置对应的识别或课程生成模型”；两项内容模型配置的服务地址、模型和 Key 均为空。

使用项目已有的小米 MiMo Key 请求同一服务的 `/models`，返回 HTTP 200，包含 `mimo-v2.5`。按现有课文识别任务，在手机加密配置中补齐文字识别与课程生成模型：`https://api.xiaomimimo.com/v1`、`mimo-v2.5`。Key 未写入源码、文档、APK 或日志。模型图片输入能力已核对[官方图片理解文档](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/multimodal-understanding/image-understanding)。

随后重试当前图片，服务已返回课文，但页面出现“模型没有返回有效的结构化内容”。进一步通过原生接口检查返回格式：结果具有 `{"text":"…"}` 外形，但字符串内部包含未转义的真实换行，`JSON.parse()` 失败。这是配置补齐后发现的第二个阻断原因。

## 修复

- [模型 JSON 解析](../src/course-library.ts)先按标准 JSON 解析；失败时，仅转义引号内未转义的控制字符，再次严格解析。保留原文中的换行、空行和制表符，不提取任意说明文字，也不补全截断 JSON。
- [Android 内容请求](../android/app/src/main/java/cn/lingonest/app/CourseContentPlugin.java)对 `api.xiaomimimo.com` 显式启用 `response_format: {type: "json_object"}` 和 `thinking: {type: "disabled"}`。其余服务请求参数保持原有协议；字段、长度和课程结构仍由原有校验处理。参数依据：[结构化输出](https://mimo.mi.com/docs/en-US/quick-start/usage-guide/text-generation/structured-output)、[深度思考](https://platform.xiaomimimo.com/docs/en-US/usage-guide/passing-back-reasoning_content)。
- 原文为空时直接填入识别结果；已有原文时继续单独展示新结果，由家长决定是否替换。
- 版本更新至 0.1.10 / versionCode 11。
